1. Pytest 基础

1.1 初始化/清除

初始化/清除功能对于自动化测试框架而言非常重要，假设现在先测试了一个注册功能，如果测试完该功能没有进行清除操作，则测试产生的数据可能会影响到后面的功能测试。

类级别的初始化（setup_class）和清除（teardown_class），只会在测试类中的测试用例执行之前和执行之后各执行 1 次，可以选择指定的类执行初始化和清除操作。

方法级别的初始化（setup_method）和清除（teardown_method），会在方法的测试用例执行之前和执行之后各执行 1 次，可以选择指定的类执行初始化和清除操作。

1.3 跳过用例执行

在自动化测试过程中，经常会遇到功能阻塞、功能未实现、环境等一系列外部因素问题导致用例无法正常执行。如果我们注释掉或删除掉，后面还要进行恢复操作就会比较麻烦，而这时我们就可以通过 skip 标签来跳过用例。

  • skip 跳过，无条件和原因：@pytest.mark.skipif()
  • skip 跳过，无需满足条件 true、有跳过原因：@pytest.mark.skipif(reason='无条件，只有跳过原因')
  • skip 跳过，需满足条件 true、且有跳过原因：@pytest.mark.skipif(条件1==1, reason='跳过原因')
  • skip 赋值变量，多处调用：myskip=pytest.mark.skipif(1==1, reason='skip赋值给变量，可多处调用')

pytest-rerunfailures 是针对全部用例进行重试，如果我想指定某些方法重试或者不重试则需要使用 flaky 插件。

语法

2.5 异常断言示例

3. Fixture 详解

使用 fixture 前须知：

  • 定义 fixture 跟定义普通函数差不多，唯一区别就是在函数上加个装饰器 @pytest.fixture()，fixture 命名不要用 test 开头，需要跟用例区分开
  • fixture 装饰器里的 scope 有四个级别的参数：function（默认）、class、module、package/session
  • fixture 可以有返回值，如果没有 return，默认会是 None；用例调用 fixture 的返回值，就是直接把 fixture 的函数名称作为参数传入
  • fixture 可以返回一个元组、列表或字典
  • 测试用例可传单个、多个 fixture 参数
  • fixture 与 fixture 间可相互调用

3.1 作为参数传递

fixture 的名字可以直接作为测试用例的参数，用例调用 fixture 的返回值，直接将 fixture 的函数名称当做变量名称。

如果用例需要用到多个 fixture 的返回数据，fixture 也可以返回一个元组，list 或字典，然后从里面去除对应数据。

3.2 前置/后置

我们在前面已经了解过如何用 setup 和 teardown 等相关函数进行初始化/清除相关操作，但是它们无法覆盖到目录级别下，并且使用起来灵活度还是没有那么高，而 fixture 这个装饰器则可以很好的解决这些问题。

3.2.1 利用参数传递

fixture 前置/后置操作能够覆盖到方法、类、模块以及目录级别，我们这里就先来看看 fixture 如何利用参数传递的方式达到 setup 和 teardown 的效果。

上面使用了 yield 语句，在 python 中，yield 是一个关键字，用于定义生成器函数。生成器函数是一种特殊的函数，可以在迭代过程中按需生成值，而不是一次性生成所有值。

当我们在上面函数中使用 yield 语句时，执行完初始化操作后函数会暂停执行，并将控制权返回给测试用例。在测试用例执行完后，就会使用这个 fixture，它会从上次暂停的地方继续执行。

简单来说，yield 语句之前的代码会在测试用例之前执行，yield 之后的代码会在测试用例执行完成之后再执行。

通过参数传递这种方式实现，我们可以发现只要不传 fixture 函数到用例中，前置/后置操作就不会实现，这样我们就可以选择性的对用例进行前置/后置除操作。

当然，传递到用例中的 fixture 函数可以是多个，这样会先进行一系列初始化操作，然后执行用例代码，最后再进行一系列的清除操作。

而前置/后置的顺序类似于 C++ 中构造函数和析构函数的初始化与清除的顺序，我们再来看个例子帮助我们理解，重点关注下面 test_02 的输出结果。

通过 test_02 的执行结果就能发现，最先执行初始化操作的 fixture 函数，在清除操作的时候就会在最后面，这也类似一个栈的先进后出的原理。

3.2.3 利用 Scope

接着，我们再来看看 setup 和 teardown 无法覆盖的目录级别，在 fixture 下是如何实现的。

conftest.py 文件使用须知：

  • 可以跨 .py 文件调用，有多个 .py 文件调用时，可让 conftest.py 只调用了一次或调用多次 fixture
  • conftest.py 与运行的用例要在同一个 pakage 下
  • 不需要 import 导入 conftest.py，pytest 用例会自动识别该文件，放到项目的根目录下就可以全局目录调用了，如果放到某个 package 下，那就在 package 内有效
  • conftest.py 配置脚本名称是固定的，不能改名称
  • conftest.py 文件不能被其他文件导入
  • 所有同目录下测试文件运行前都会执行 conftest.py 文件

如果想对一个目录下的所有文件进行公共的初始化和清除操作，就可以在该目录下创建一个 conftest.py 的文件，在这里编写目录公共的初始化和清除代码。

这里的 scope 一共有 4 个选项，每个选项执行的效果都不同：
- function（默认）：fixture 函数只在当前测试函数中生效。
- class：fixture 函数在当前测试类中生效，所有该测试类中的测试函数都会共享这个 fixture 函数创建的资源。
- module：fixture 函数在当前测试模块中生效，所有该测试模块中的测试函数都会共享这个 fixture 函数创建的资源。
- package/session：fixture 函数在当前测试包或会话中生效，所有该测试包或会话中的测试函数都会共享这个 fixture 函数创建的资源。

  • 测试类中只要有一个测试用例的参数中使用了 class 级别的 fixture，则在整个测试类的所有测试用例之前都会去执行 fixture 定义的动作，以及此测试类的所有用例结束后同样要运行 fixture 指定的动作。
  • 如果在类外的函数中去使用 class 级别的 fixture，则此时在测试类外外每个测试用例中，fixture 跟 function 级别的 fixture 作用是一致的，即在类外的函数中引用了 fixture，则在此函数之前和之后同样去执行 fixture 定义的对应的操作。
