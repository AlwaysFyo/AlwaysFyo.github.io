1. 数据驱动

1.1 测试数据参数化

参数化测试 是一种 “数据驱动测试” (Data-DrivenTest)，在同一个方法上测试不同的参数，以覆盖所有可能的预期分支的结果。它的测试数据可以与测试行为分离，被放入到文件、数据库或者外部介质中，再由测试程序读取。

Python 标准库中的 unittest 自身不支持参数化测试，为了解决这个问题，有人专门开发了两个库：一个是 ddt，一个是 parameterized。

数据驱动思想：数据和用例进行分离，通过外部数据去生成测则试用例。

2. Mock 接入

2.1 Mock 背景

在一些特殊场景下，我们一些服务可能会比较不稳定或者还没有开发完，会出现一些不可控的因素，而上游急着需要调用下游的这些服务来观察自身服务是否符合预期。

那么我们可以通过 Mock 的方式，Mock 出下游（也就是通过模拟的方式，实现一个下游的替身出来），从而可以使用 Mock 的替身提前测试自身服务。

常见 Mock 适用场景：

  • 前后端联调：当前端需要的接口后端还在开发，就可以使用 mock 模拟后端返回我们需要的数据。
  • 单元测试：当我们所要测试的接口还未开发完，而我们还要完成测试用例代码的编写，我们可以先模拟这个接口进行测试。
  • 屏蔽无关的真实服务：专注于要测试服务本身，而其它服务又不在本次测试范围内，则可以使用 mock 只模拟出我们关注的服务。
  • 依赖第三方接口：当我们的接口需要调用第三方，而第三方接口我们还未得到权限或未购买时，可使用 mock 模拟进行测试。

注意 mock 只适合用于临时的测试，而不能代替真实场景的测试。

例如，我现在有个服务需要调用下游的支付服务，通过这个下游服务的返回值来决定之后该怎么执行：

  • 当返回值状态码为 200，则表示支付成功，我当前服务就可以执行后续逻辑
  • 当返回值状态码为 500，则表示支付失败，需要做一些异常的处理逻辑

如果此时下游的支付服务出现问题，或者没有开发完毕，无法提供这个返回值，而我此时有想验证一下我后续代码的处理逻辑，则可以通过 Mock 的方式模拟返回值的状态码，从而可以执行后续逻辑并进行观察。

2.2 Mock 使用

如果你的团队技术基础很好，开发能力很强，那么我建议你用对应语言的 Mock 框架，例如 Java 语言的 Mockito （https://github.com/mockito/mockito）框架和 Python 语言的 mock 框架（https://pypi.org/project/mock/）。

如果你的团队技术基础相对比较薄弱，那么我推荐你看看 moco，这个框架在开发 Mock 服务的时候，提供了一种不需要任何编程语言的方式，你可以通过撰写它约束的 Json 建立报务，并通过命令启动对应的服务，这就可以快速开发和启动运行你需要的 Mock 服务（项目地址：https://github.com/dreamhead/moco/）。

2.2.1 unittest.mock 类

官方文档：https://docs.python.org/dev/library/unittest.mock.html

Mock 类库是一个专门用于在 unittest 过程中制作（伪造）和修改（篡改）测试对象的类库，制作和修改的目的是避免这些对象在单元测试过程中依赖外部资源（网络资源，数据库连接，其其它服务以及耗时过长等）。

使用前须知

  • Python2.x 的版本，mock 是一个独立的模块，需要用 pip 安装
  • 从 Python3.3 以后的版本，mock 已经合并到 unittest 模块中了，是 unittest 单元测试的一部分，直接导入过来就行

2.2.2 Mock 技术栈选型

  • 简单是第一要素，需要将学习成本降到最低
  • 处理速度比完美的 mock 服务更重要

3. 测试报告

Unittest 测试默认结果输出是比较简单的，即使通过指定 -v 参数得到详细输出，也就只是在默认输出内容的基础上，额外显示了用例名称，还达不到一份测试报告的标准，而是一份日志信息。

3.1 HTMLTestRunner

最新版：https://github.com/oldani/HtmlTestRunner

汉化版：https://github.com/wangquansheng/HTMLTestRunner\_cn

如果想要生成 HTML 格式的报告，那么就需要额外借助第三方库（如 HTMLTestRunner）来操作。

HTMLTestRunner 是一个第三方的 unittest HTML 报告库，首先我们下载 HTMLTestRunner.py，并放到对应目录下或者放到 …/python\Lib 目录下。

Tips：

这里我们使用的是汉化版的报告库。

然后可以在写测试用例的文件中导入这个 HTMLTestRunner.py 文件。

  • HTMLTestRunner 类说明：
    • stream：指定报告的路径
    • title：报告的标题
    • description：报告的描述
  • run() 方法说明：
    • suit：运行的测试套件
    • rerun：重跑次数
    • save_last_run：是否保存最后一个结果

我们运行后，在当前目录下就会生成一个 result.html 文件，将其以浏览器的方式打开，就能看到一份视图化的测试报告了。

3.2 BeautifulReport

项目地址：https://github.com/TesterlifeRaymond/BeautifulReport

仓库地址：https://www.cnpython.com/pypi/beautifulreport

BeautifulReport 是一个基于 unittest.TestReport 模块实现的测试用例模板，可以把我们每次测试中的结果通过 BeautifulReport 整合成一个可视化的报表。
